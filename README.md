# 短连接生成器

面向 macOS 和 Windows 的桌面链接管理工具。连接 Cloudflare 账户，为自己的域名创建短链接，并分别设置中国大陆访客与其他地区访客打开的网址。

应用在本机运行，直接调用 Cloudflare API。没有中央账户服务，不收集访问统计。关闭客户端后，已配置的链接仍由 Cloudflare Workers 提供跳转。

完整操作与验收步骤见 [使用指南](docs/QUICK-START.md)。

## 使用流程

1. 在「Cloudflare 账户」中打开令牌创建页，确认权限后创建令牌，并粘贴到客户端。
2. 在「域名管理」中填写域名。应用检查所属账户和已有配置，提示需要处理的问题。
3. 核对修改范围，确认后连接域名。
4. 在「短链接」中填写短链接名称，直接输入两个跳转网址，或选择已保存的平台地址并填写自己的邀请码。
5. 确认保存后，检查短链接跳转和网站访问结果。检测失败会标红；无法确定的结果会显示黄色。

例如：`https://example.com/go/guide`。访客请求中附带的查询参数不会追加到目标地址；保存的目标地址自己的查询参数会保留。

只有国家代码 CN 使用中国大陆目标；香港、澳门、台湾及未知地区使用默认目标。地区判断依据是 Cloudflare 观察到的网络出口。签名自检验证分流结果，不代表目标网址在当地网络一定可访问。

## 平台地址与检测

平台地址保存一个其他地区地址和一个或多个中国大陆备用地址。每条短链接选择一个平台并保留各自的邀请码。修改邀请码前的地址后，所有引用它的链接随配置传播自动使用新地址，不需要逐条替换。需要保留查询参数时，可设置邀请码后面的额外参数。

目标访问检测与跳转自检分开显示。目标检测使用本机直连，不经过系统代理；开启代理的浏览器可能得到不同结果。成功结果只说明这次直连能访问；验证码、限流和超时保持未知，不推断当地可达性。结果带检测来源与时间，配置变更后需要重新检测。

可为账户连接一个自己信任的中国大陆检测服务。它必须实现 [检测协议](docs/POOLS.md)，并使用实际中国大陆网络节点。开启后，云端约每 15 分钟检查池内备用地址，连续三次明确失败才停用，连续两次成功后恢复。服务故障不会当成目标故障；过期证据不继续被当成当前结论。所有备用地址近期都确认不可用时，返回暂时不可用，不偷偷切换到其他地区的目标。

检测服务默认未配置。仓库提供可自行部署的 [参考检测服务](probe/README.md)。本项目不会自动购买服务或创建中国大陆节点；仅靠 Cloudflare 节点无法确认当地可达性。签名能验证返回结果来自已配置的服务，不能证明其实际网络位置。

## 凭据与数据

- 令牌、自检密钥和可选检测服务密钥存放在系统凭据库。应用配置只保存非机密引用。
- 移除账户只清除本机配置与对应凭据。删除云端资源需要单独确认。
- 修改前生成短时有效的变更计划。操作中断后保留恢复记录，不把不确定的结果显示为成功。
- 配置导出不含令牌或任何检测密钥，但含你的域名与目标地址，请作为私人备份保存。
- 从云端找回配置时先核对资源关系；丢失的自检密钥通过独立确认后重新生成。
- 云端配置更新需要时间。显示「等待生效」时，可稍后重新检测。

## 支持的平台

构建目标为 Apple 芯片 macOS、Intel macOS 和 Windows x64。各平台的原生构建、安装和网络验证须分别完成；交叉编译不等于原生验收。

当前源码是发布候选开发版本。是否存在已验证安装包，以具体版本的发布记录为准。

macOS 候选包采用临时签名，未经过 Apple 公证。首次打开可能需要在系统设置的「隐私与安全性」中确认来源。Windows 候选包未做 Authenticode 签名，系统可能显示未知发布者。请核对下载来源和校验和。应用更新使用独立的 Tauri 签名；未配置真实公钥和发布地址时，客户端会明确显示更新渠道不可用。

## 开发

需要 Node.js 24、Rust stable 及对应平台的 Tauri 2 编译环境。

```sh
npm ci
npm run build
npm test
npm run test:edge
npm run test:probe
npm run test:tooling
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
cargo fmt --manifest-path src-tauri/Cargo.toml --check
npm run desktop:dev
```

仅查看界面可运行 `npm run dev`，访问开发服务并加 `?preview=1`。预览模式使用明确标注的示例数据，不连接 Cloudflare，不保存真实令牌。桌面应用正常启动时不载入示例账户。

## 公开发行前的检查

启用本地推送钩子：`git config core.hooksPath .githooks`。私有词表保存在仓库外的用户配置目录 `short-link-generator/denylist.txt` 中；缺失或为空会拒绝推送。钩子检查待推送提交的完整可达历史、提交说明、文件名和内容。工作区检查不能代替历史检查。短词可能命中第三方完整性哈希或二进制符号，需人工核对；工具不会自动忽略这些命中。

普通 CI 只执行标准 Linux 托管任务。原生专项检查由手动选择平台触发；发行矩阵在本机和单平台预检通过后运行。项目不使用自托管 runner，不在 PR 工作流中使用发布密钥。

发布需要预先配置受保护的 `release` 环境：

- `PRIVACY_DENYLIST` secret：私有词表内容，仅写入临时 runner 的用户配置目录。
- `TAURI_SIGNING_PRIVATE_KEY` secret，以及可选的 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。
- `UPDATER_PUBLIC_KEY` variable：与上述私钥配对的 Tauri 更新公钥。

发版流程固定检查通过的提交，分别在三个原生 runner 上测试、构建、解包扫描，再生成带签名的更新清单及校验和，汇总为草稿 Release。最终公开前仍需完成安装、更新、代理开关、专用测试域名和匿名下载检查。不要提交真实配置、私有截图、日志或用户备份。
